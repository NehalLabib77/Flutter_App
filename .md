# Recommendation Model

EduCompass uses **TF-IDF + Hybrid Ranking**.

TF-IDF processes weighted course information:

```text
Course Name      ×4
Skills           ×4
Subject          ×3
Description      ×2
Level            ×2
Course Type      ×1
Certificate      ×1
Organization     ×1
Provider         ×1
Instructor       ×1
```

The vectorizer uses:

```text
Unigrams + Bigrams
20,000 maximum features
English stopwords
Sparse matrix
```

Model files are located in:

```text
ml/artifacts/models/v4/
```

Important artifacts:

```text
courses.csv.gz
tfidf_vectorizer.joblib
tfidf_matrix.npz
model_config.json
model_metadata.json
```

# Hybrid Recommendation

Recommendations combine:

```text
TF-IDF Content Similarity
+
User Preferences
+
User Behavior
+
Course Quality
+
Popularity
```

Behavior weights include:

```text
View       = 1
Favorite   = 3
Enroll     = 5
Complete   = 7
```

For example, **For You** roughly uses:

```text
45% Content
20% Behavior
15% Preferences
10% Quality
10% Popularity
```

Different sections use different priorities:

* **Popular Right Now** → popularity is strongest
* **Top Rated** → quality/rating is strongest
* **For You** → personal behavior + preferences
* **By Your Goal** → typed goal/content similarity is strongest

# Enrollment / My Courses

Enrollment has three layers:

```text
SQL Enrollment
    → durable source of ownership

Firestore
    → cloud synchronization

SharedPreferences
    → local fast cache
```

Each account uses a separate local key:

```text
enrolled_course_ids_user_<userId>
```

This prevents Account A courses from appearing in Account B.

Backend enrollment API:

```text
GET    /api/v1/me/enrollments
POST   /api/v1/me/enrollments
DELETE /api/v1/me/enrollments/<course_id>
```

Deleting an account removes preferences and profile activity but preserves:

```text
Enrollments
Payments / Order History
```

If the same email registers again, preserved enrolled courses can be restored.

# SSLCOMMERZ Payment

Paid-course payment is handled securely by Flask.

Important backend files:

```text
backend/app/billing_service.py
backend/app/payment_routes.py
backend/app/database_models.py
```

Flutter files:

```text
lib/services/billing_provider.dart
lib/screens/mock_payment_screen.dart
lib/screens/payment_status_screen.dart
lib/services/deep_link_service.dart
lib/api_client.dart
```

Payment flow:

```text
Course selected
↓
Flutter sends course_id
↓
Backend determines real price
↓
Payment record created
↓
SSLCOMMERZ sandbox session
↓
User completes gateway payment
↓
SSLCOMMERZ callback/IPN
↓
Backend validates transaction independently
↓
Enrollment created
↓
Deep link returns to Flutter
↓
Flutter checks backend payment status
↓
My Courses updates
```

Flutter never controls the actual payment amount.

Important APIs:

```text
GET  /api/v1/payments/provider
POST /api/v1/payments/sslcommerz/session
POST /api/v1/payments/sslcommerz/ipn
GET  /api/v1/payments/sslcommerz/status/<transaction_id>
GET  /api/v1/payments/history
```
